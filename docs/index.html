Lost in the Flow with Code Talkers: Unveiling the Instruction-Tuning Tax of Large Language Models in Code Tasks

Chang Shi Ying*, Chiok Yew Ho*, Yichen Li, Yintong Huo

Singapore Management University and The Chinese University of Hong Kong

*Equal contribution

Paper Code Models

Abstract

Modern coding assistants must operate in two different settings. In Flow mode, developers expect localized completion or infilling inside an unfinished program. In Command mode, they express intent in natural language and expect executable code in return. This paper studies whether instruction tuning is equally beneficial for both modes.

Across matched Base and Instruct variants of Qwen2.5-Coder and DeepSeek-Coder, the paper shows that instruction tuning is not a free lunch. It often improves instruction-oriented tasks and guidance-heavy completion, but can weaken infilling and change generation behavior in ways that matter for real-world coding assistants. The study combines benchmark comparisons, failure analysis, behavior-oriented metrics, and intermediate-checkpoint evaluation to characterize this trade-off as the Instruction-Tuning Tax.

Why This Matters

The motivating example in the paper shows the core concern: instruction-tuned models may generate extra code around the target span, even when the desired answer is a concise local insertion.

That matters because the assistant behavior needed for a chat-style instruction is not the same as the assistant behavior needed for a precise fill-in-the-middle suggestion inside a live codebase.

Study Overview

The page follows the structure of the paper: a conceptual framing around Flow and Command modes, a benchmark-based endpoint comparison, a failure analysis, behavior-level metrics, and a controlled replication of the instruction-tuning trajectory.

Finding 2

Instruct models generally perform better with guidance, but they improve on natural-language cues at the expense of code infilling.

The contrast is especially visible in ClassEval: completion tasks include to-do descriptions or docstrings, while infilling tasks require a precise local insertion inside existing code.

Why completion and infilling diverge

  • Completion tasks embed natural-language guidance in comments or docstrings.
  • Infilling tasks require the model to stay within a local hole defined by prefix and suffix context.
  • Instruct variants often improve on ClassEval-Completion while degrading on ClassEval-Infilling.
  • This suggests stronger dependence on natural-language cues, but weaker local insertion discipline.

Finding 3

There is no guarantee of eliminating the instruction-tuning tax with increasing model size.

The effect of size is model-specific. Qwen shows consistent base-vs-instruct differences across many settings, while DeepSeek becomes less consistent on some benchmarks but remains highly degraded on structured infilling.

Finding 4

Base and instruction-tuned models share substantial overlap, but their exclusive successes differ by task.

Base models exclusively solve more fill-in-the-middle problems, whereas instruction-tuned models exclusively solve more completion problems.

Finding 5

Manual failure analysis shows that most failures remain functional mismatches, but instruction tuning shifts more errors toward verbosity-related modes.

After instruction tuning, failures are more likely to include extra or redundant code and irrelevant natural language.

Selected shifts from the manual analysis

  • HumanEval Infilling, Qwen2.5-Coder-7B: redundant-code failures rise from 10% to 48%.
  • HumanEval Infilling, DeepSeek-Coder-6.7B: redundant-code failures rise from 42% to 94%.
  • ClassEval Completion, Qwen2.5-Coder-7B: redundant-code failures rise from 6% to 48%.
  • ClassEval Completion, DeepSeek-Coder-6.7B: redundant-code failures rise from 34% to 98%.

Finding 6

The behavioral metrics show that the verbosity trend is systematic across outputs.

Instruction-tuned models are more likely to introduce natural language or unnecessary definitions/classes, especially in weakly constrained completion tasks.

Finding 7

Instruction tuning affects capabilities unevenly across benchmarks, and later tuning stages reallocate capability rather than uniformly improving all forms of code generation.

Instruction-following ability improves, completion remains positive on average but weakens in later stages, and infilling declines across the replicated tuning trajectory.

Discussion and Implications

For researchers

  • Instruction-tuning tax is not uniform across model families, which suggests model-specific interactions between architecture, pretraining, and post-training.
  • Robust post-training should preserve concise, boundary-aware continuation for flow-mode tasks such as infilling.
  • Behavior metrics are important because the trade-off is visible in how models fail, not only in whether they pass.

For practitioners

  • Model selection should be guided by deployment mode, not by one aggregate score.
  • Safeguards should target dominant failure modes such as verbosity, natural-language leakage, and unnecessary declarations.
  • Routing flow-oriented and command-oriented tasks differently may be more effective than treating instruction tuning as a universal upgrade.
